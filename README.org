*1. Persistent translation cache — chrome.storage.local (NOT SQLite).*

A genuine SQLite engine (=sql.js=) inside a content script would mean
shipping ~1 MB of WASM, syncing it with IndexedDB underneath, and
loading it on every Netflix page just to do key→value lookups. The
plugin's only access pattern is "given (srcLang, tgtLang, text), do
we have a translation?" — exactly what =chrome.storage.local= is
built for: persists across reloads/restarts/browser-relaunches, no
extra dependencies, no schema, no bundle bloat. Behavior identical
to a single =SELECT translation FROM cache WHERE k = ?=. If a true
SQL surface ever becomes useful (ad-hoc queries, bulk export,
cross-deck stats), swap in =sql.js= without changing the call sites
— the cache is encapsulated.

Implementation:
- =transKey(src, tgt, text) → "nstTr:v1:<src>:<tgt>:<text>"=. The
  =v1= prefix lets us invalidate the schema later by bumping it.
- =transCacheGet(src, tgt, text, cb)= hits an in-memory L1 first
  (=transMem= object) and falls back to =chrome.storage.local.get=.
  On any disk hit, the value is promoted into L1 so subsequent
  identical subtitles are a synchronous lookup.
- =transCacheSet(src, tgt, text, translation)= writes ={t, ts}= to
  =chrome.storage.local= and also primes L1. =ts= is unused for now
  but lets a future eviction job drop entries older than N days.
- =autoTranslate()= was refactored: it now calls =transCacheGet=
  first; on hit, =applyTranslation()= is invoked synchronously
  (well, after the storage callback) and no network call is made.
  On miss, the existing =loadJson(gtansUrl(...))= path runs and
  =transCacheSet= writes the result back before
  =applyTranslation()=. Logs distinguish the two paths:
  =[NST] auto-translation (cached): ...= vs =[NST] auto-translation: ...=.

Side benefit: the cache is keyed by *text*, not by URL, so two
different Netflix sessions that subtitle the same line ("Yes.",
"What?", song choruses) reuse the same translation across episodes
and across days — Google Translate is hit at most once per unique
=(src, tgt, text)= triple, ever.

Caveat: =chrome.storage.local= has a per-extension quota of ~10 MB
(unlimited if =unlimitedStorage= permission is requested). At ~150
bytes per entry, that's ~70k cached subtitles — plenty for years of
casual viewing, but if you binge-translate everything we'd want to
add an LRU eviction pass. Not added yet.

  =initSqlJs({ locateFile: f => chrome.runtime.getURL('vendor/sqljs/'+f) })=.
- Total extension size grows by ~700 KB. One-time download per
  install, then served locally.

** Persistence below sql.js

sql.js holds the database in WASM linear memory and loses it on page
reload. To survive reloads, =nstDB= serializes the entire DB via
=db.export()= → =Uint8Array=, stores as =Array.from(bytes)= under
=chrome.storage.local["nstSqliteDump:v1"]={bytes,savedAt}=, and
reconstitutes with =new SQL.Database(dump)= on next page load.
=scheduleSave()= debounces writes to 2 s after the last mutation so
rapid translation arrivals coalesce into one write.

Considered IndexedDB and OPFS (true per-row persistent SQLite via
=sqlite-wasm-opfs=) but rejected for v1.17: at expected DB sizes
(<5 MB even after many videos) the whole-DB-blob approach in
=chrome.storage.local= is dramatically simpler and well within the
~10 MB extension quota.

Per the user note, =videos.url= is the canonical form
=https://<host>/watch/<id>= (via new =getCanonicalWatchUrl()= helper),
stripping the =?trackId=...&tctx=...= junk Netflix appends.

** Status semantics & retry loop

- =ok= — translation present, never retry.
- =pending= — captured but the Google fetch never resolved before the
  tab closed.
- =failed= — fetch returned an error / empty translation.

On =run()= we call =nstDB.loadVideoSubtitles(videoId)=; the returned
rows are pushed into =captures= (with =preloaded:true=) and rendered
into the panel before any live subtitle ever arrives. Each row whose
=translation= is missing or whose =status= is =pending=/=failed= is
added to =retryQueue=, which =pumpRetry()= drains serially (one
=loadJson= in flight at a time, 250 ms gap between requests) to avoid
tripping Google Translate's anti-bot heuristics. Each retry result
updates the row's =status= and =attempts= via
=INSERT ... ON CONFLICT ... DO UPDATE SET attempts=subtitles.attempts+1=.

** Wiring

- =autoTranslate(sentence, entry, done?)= now (a) consults
  =cache_translations= first, (b) records =pending= in =subtitles=
  before the network call (so a crashed tab leaves a recoverable
  marker), (c) records =ok= + translation on success, (d) records
  =failed= on network/parse error. The optional =done= callback is
  used only by the retry pump for serialization; live captures fire
  and forget.
- =loadJson()= now calls its callback with =null= on fetch failure
  (previously the failure path was a silent =.catch=), so
  =autoTranslate= can distinguish "no answer" from "empty answer".
- =upsertVideo()= is called once per =run()=; =recordSubtitle()= on
  every new live subtitle and every retry. Both schedule a debounced
  save.

** Migration

On first launch, =maybeMigrateLegacyCache()= scans
=chrome.storage.local= for keys with the v1.16 prefix =nstTr:v1:=,
copies them into =cache_translations=, deletes the originals, and
saves. One-shot; subsequent launches see no legacy keys and skip the
work.

** Caveats

- The 2 s debounced save means closing the tab within 2 s of the
  *last* translation may lose that translation (and a few preceding
  ones queued in the same window). Could be mitigated with a
  =beforeunload= flush, not added in v1.17.
- =scheduleSave()= writes the whole DB blob every time. At ~50 KB per
  watched movie this is fine, but if the cache grows past 1–2 MB the
  =chrome.storage.local.set= calls start to add up. The natural
  upgrade path is OPFS via =sqlite-wasm-opfs=, kept in mind but not
  shipped yet.
- =recordSubtitle= keys on =(video_id, video_time, original)=. If
  Netflix re-encodes the same line with a slightly different
  =currentTime= on a different session (sub-millisecond differences
  in mp4 timestamps), we may double-store it. Cheap, harmless,
  ignored.
- The retry pump and the initial preload race: a live subtitle that
  arrives while a retry is in flight goes through the normal
  =readAndHandle= path (which dedups via =findExistingCapture=
  ±3 s); the retry only updates an existing row.

** Future work enabled by SQLite

The user explicitly flagged "I might want to export from the sqlite
file directly to .org mode." With the schema above this becomes a
single =SELECT= per video plus the existing org formatter — no new
data model needed.

languages, select language A in Netflix's menu, wait for cues to populate,
