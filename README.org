Implemented in v1.13. Files touched: =content-script.js=, =manifest.json=.

Four coordinated changes turn the panel from "growing tape" into "list
that tracks playback":

1. *Non-linear mode flag* — =window.__nstNonLinear= is set =true= in two
   places:
   - =seekVideo()= sets it the moment the user click-/dblclick-seeks
     from the panel (we know our own intent).
   - =attachVideoSeekWatcher()= polls =document.querySelector('video')=
     every 500 ms, attaches a =seeking= listener once, and also
     compares =currentTime= deltas — if =Math.abs(now - lastT) > 1.5=
     it flags a manual scrub on Netflix's progress bar (which we
     can't intercept directly because Netflix re-renders the seek bar
     in its own React tree). The flag clears automatically once the
     poll has seen ~1.5 s of clean monotonic forward playback after
     the seek.

2. *Dedup on jump-back* — =readAndHandle()= now calls
   =findExistingCapture(subtitle, vt)= before inserting. The match
   criterion is "same =original= text AND =|videoTime - vt| <= 3s=",
   which avoids false-positive merges on repeated lines (chorus
   lyrics, recurring "Yes." / "No.") while still recognizing the same
   line on a re-seek. On a hit we look up the existing =<dl>= (cached
   on =entry.dl= or refound by =data-vt=) and =scrollIntoView({block:
   'center'})= instead of inserting a new row. Also relaxed the
   =subtitle === subtitleBefore= guard to allow re-processing while
   non-linear, so seeking back to the currently-displayed line still
   triggers the scroll-to-existing path.

3. *Sorted insert when seeking forward into new territory* —
   =subtitleSentence().add()= scans existing =dl[data-vt]= rows and
   inserts the new =<dl>= =beforebegin= the first row whose
   =data-vt > ts=, falling back to =append= only when the new
   subtitle is later than every existing one. The result: scrubbing
   to an earlier point and watching forward inserts new rows in the
   middle of the list at their correct chronological position.

4. *Scroll target depends on mode* — =scroll(insertedDl)= and the
   post-translation rAF in =autoTranslate()= now branch on
   =window.__nstNonLinear=. In non-linear mode they
   =insertedDl.scrollIntoView({block: 'center'})= so both the
   original and (when it arrives) the translation are guaranteed
   visible. In linear mode the original "snap to bottom when panel
   is open" behavior is preserved.

Also: each =captures= entry now carries a =dl= back-reference, set
right after =add()= via a =data-vt=-based lookup; =autoTranslate=
writes the translation into =entry.dl= rather than =dls[last]=, so
sorted-inserted middle rows get their translation written into the
correct row instead of overwriting the last visible row.

Caveats:
- =findExistingCapture= uses a ±3 s window. If you seek to a part of
  a long-held subtitle (e.g. a 7-second song line) ~6 s past where it
  was originally captured, dedup will miss and you'll get a
  duplicate row at the seeked time. Widening the window would
  conversely risk merging genuine repeats.
- The progress-bar seek detector is heuristic: it watches
  =currentTime= deltas. Very short seeks (<1.5 s) won't flip the
  flag, but the panel UX is unchanged in that case (we were near
  that subtitle anyway).
- The non-linear flag auto-clears after ~1.5 s of monotonic
  playback, so the panel reverts to "scroll to bottom" once you let
  it play linearly again.

Fixed in v1.14. Files touched: =content-script.js=, =style.css=,

Root cause of bug 1 was =setPointerCapture()= introduced in v1.11: once
the handle captures the pointer, *the capturing element's cursor
applies everywhere on the page* until =releasePointerCapture()= runs.
Any =pointerup= that didn't reach the handle (e.g. release happened
over a Netflix overlay that called =stopPropagation=, or the focus
left the window mid-drag) left the capture in place and the
ew-resize cursor stuck globally — which on Netflix's player chrome
masked the timestamp's =cursor:pointer= too (bug 2 was a symptom of
bug 1, not an independent CSS problem).

Rewrote =setupResize()= without pointer capture:
- =mousedown= on the handle starts the drag, =mousemove= / =mouseup=
  are listened on =window= in the *capture phase* (so Netflix
  =stopPropagation= can't swallow them) plus a =window.blur= and
  =document.mouseleave= belt-and-suspenders to end the drag if focus
  leaves.
- During drag, a transparent full-viewport =<div id="nst-drag-overlay">=
  (=position:fixed; inset:0; z-index:2147483647; cursor:ew-resize=) is
  appended; it shows the resize cursor globally without touching any
  pointer-capture API. On =mouseup= the overlay is removed and the
  cursor reverts immediately.
- Body =cursor= is no longer mutated at all; the overlay alone owns
  the drag-time cursor, so there's nothing to "leak" if cleanup is
  missed (and if cleanup *is* missed, you just see a transparent div
  — easier to notice and recover from than a stuck OS cursor).

For bug 2, also hardened =.nst-ts= CSS: =cursor:pointer !important= on
both rest and =:hover= states (defensive against any future inline-style
override), plus a hover =text-decoration:underline= so the affordance is
visible even before the cursor changes.
